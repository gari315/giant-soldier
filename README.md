# 巨人 対 兵士（オンライン対戦）

ブラウザゲーム「巨人討伐」をベースにした、巨人1人（手動操作）対 兵士最大4人のオンライン対戦です。
Render の Web Service（Node.js）が **ゲームの配信（HTTP）** と **WebSocket 通信** の両方を担当します。
タイトル画面で「ソロ」（従来のウェーブ制）と「オンライン対戦」を選べます。

## 構成

| ファイル | 役割 |
|---|---|
| `server.js` | 静的配信 + `/healthz` + WebSocket（部屋・ロビー・同期・勝敗判定） |
| `public/index.html` | ゲーム本体（three.js r128 は cdnjs の固定バージョン） |
| `public/net.js` | 通信・ロビー・巨人操作・同期表示・観戦・結果画面 |
| `public/bgm.mp3` | BGM（元の HTML から切り出し） |
| `scripts/bot.js` | テスト用ボット / サーバーの自動検証 |
| `render.yaml` | Render 用設定（free プラン） |

## ローカルで起動

Node.js 18 以上が必要です。

```bash
npm install
npm start            # http://localhost:3000
```

ブラウザのタブを2〜3個開き、1つ目で「オンライン対戦 → 部屋を作る」、他のタブで表示された4文字のコードで「参加」します。
役割（巨人は1人まで）を選び、ホストが「開始」を押します（最少2人）。

### ボットで動作確認

```bash
npm test                                                  # 部屋・判定ロジックの自動検証（別ターミナルで npm start 済みなら不要。単体で起動しているサーバーに接続）
node scripts/bot.js --room ABCD --count 3                 # 兵士ボット3体を部屋 ABCD に参加させる
node scripts/bot.js --room ABCD --role giant              # 巨人ボットを参加させる（人間2人が揃わなくても開始できる）
node scripts/bot.js --selftest --url ws://localhost:3000  # 接続先を指定
```

`npm test` は `npm start` を起動した状態で実行します。

## Render にデプロイ

1. [Render](https://render.com/) にログインし、GitHub アカウントを連携します。
2. **New + → Blueprint** を選び、push したリポジトリを指定します（`render.yaml` が読まれます）。
   手動で作る場合は **New + → Web Service** で、Runtime: Node / Build Command: `npm install` / Start Command: `npm start` / Plan: Free、Health Check Path: `/healthz`。
3. デプロイ完了後、`https://<サービス名>.onrender.com` を開けば遊べます。URL を友達に送ってください。
   クライアントは同一オリジンの `wss://` に自動接続します（URL の書き換えは不要です）。

### 無料プランの注意

- 一定時間アクセスがないとサービスが停止し、次のアクセスで起動に最大1分ほどかかります。
  接続待ちの間は「サーバーに接続中…」と表示され、自動で再試行します。
- サーバーは 25 秒ごとに WebSocket の ping を送って接続を維持します。
- 部屋はメモリ上にあるため、再起動すると消えます。

## 遊び方

| | PC | スマホ |
|---|---|---|
| 兵士 | 既存どおり（WASD / マウス / Q・E ワイヤー / Shift ガス …） | 既存どおり |
| 巨人 移動 | WASD（向きはカメラ基準）、マウスで視点 | 左スティック |
| 巨人 走る | Shift | 「走る」ボタン |
| しゃがむ（押している間） | G | 「しゃがむ」（押している間。移動は半分の速さ） |
| 蹴り（周囲すべてが対象） | 右クリック / Space | 「蹴り」 |
| うなじ守り | C | 「うなじ守り」 |
| 咆哮（位置を強調表示） | T | 「咆哮」 |
| 手を伸ばす | E 長押し = 画面中央（照準）へ近い方の手を伸ばす / Q 長押し = 両手 | 「🖐 手を伸ばす」をONにして、画面の右側をタッチ／ドラッグした場所へ |
| カメラ調整（三人称） | ホイール / Z・X=ズーム、R・F=高さ | 右上の「拡・縮・上・下」ボタン |
| 視点（三人称/一人称） | V | 左上の視点ボタン |

- **兵士の勝ち**: 巨人のうなじを背後から斬る。 **巨人の勝ち**: 兵士全員を食べる／つぶす。
- 巨人の**手に触れた兵士は、いつでも自動で掴まれます**（向き・状況を問わず、掴むボタンはありません）。掴まれた兵士は約2.5秒後に食べられ脱落します。蹴りは全方向（360°）が対象で、半径 16×スケール・高さ 22×スケール以下の兵士が脱落します。**予備動作が約1.1秒**あり（脚を引く・腕を広げる・上体をそらす＋足元に赤い危険範囲が満ちていく）、満ちた瞬間に判定します。クールダウンなし、モーション約1.8秒の間は連打不可。脚を失うと・しゃがみ中は蹴れません。
- うなじ守りは持続1.5秒・**クールダウンなし・1試合3回まで**（残り回数はボタンとHUDに表示。発動中の重ね掛けは不可。`server.js` の `GUARD_MAX` で変更）。発動中はうなじを斬れず、巨人も動けません。通信遅延で守りが負けないよう、うなじ申告は0.25秒保留され、守り終了後も0.25秒は無効です。
- 脱落した兵士は観戦になり、クリック / Tab で巨人・生存兵士の視点を切り替えられます。
- ズームが戻らない・スティックが固まったときは、ポーズ画面の **「画面リセット」** を押してください（ズーム、スティック、ボタンの押しっぱなしを解除します。試合は続行できます）。
- ガス補給所（背の高い建物の屋上に2か所、緑の円盤）で兵士のガスが回復します。
- **咆哮**（クールダウン14秒・唯一のクールダウン）: 4秒間、全兵士の光の柱が太く赤くなり、名前も大きく表示されます。兵士にも通知されます。
- **居場所の見え方**: 巨人の画面では、全兵士の名前・距離が常に表示され、画面外の兵士は端に矢印で出ます。兵士は2倍の大きさで描画され、壁越しでも見える光の柱が立ちます。ダッシュ・斬撃・高速移動では蒸気の軌跡も出ます。
- 兵士は、巨人の視線（正面±約33°・距離110以内・建物に遮られない）に入ると「⚠ 巨人に見られている！」と警告されます。
- **手の危険範囲の表示**: 巨人の両手のまわりに、掴まれる範囲（半径4×スケール）が赤い光で表示されます。兵士が近づく（14×スケール以内）と強く光ります。
- **蹴りの衝撃波**: 蹴り出した瞬間、足元から赤い衝撃波の輪が約0.35秒で全範囲に広がり、当たる高さを示す赤いドームも出ます。兵士には波が届いた瞬間に、赤フラッシュ・画面揺れ・スローモーションが入ります。
- **決着の演出**: うなじを斬った瞬間は白フラッシュとスローモーションになり、うなじ（全滅の場合は巨人の頭）のまわりをカメラが回りながら「うなじを斬った！」「うなじを斬られた…」などが大きく表示されます（約2.6秒）。そのあと結果画面になります。
- **兵士の見えやすさ（巨人側）**: 兵士は遠いほど大きく描画されます（判定は変わりません）。画面上の位置には色つきのリングが常に付き、名前・距離・光の柱もあります。兵士ごとに色が違い、ミニマップの点と名前の色も一致します。ワイヤーは明るい色になり、ガス噴射の蒸気も大きく出ます。
- **巨人の操作の改善**:
  - 移動: スティックを倒した向きへ素直に進みます。旋回が速くなり（標準 1.6→2.6）、向きが目標に近いほど速く進む（旋回しながら歩ける）ようにしました。加速も速くなっています。スティックを押している間は進行方向の基準を固定するので、カメラが自動で回っても進路が曲がりません。
  - カメラ追従: 歩いている間、カメラがゆっくり巨人の背後へ回り込みます（視点を手で動かした直後の約1.2秒と、一人称では動きません）。
  - 腕スティック: 倒す向き=手の方向、倒し量=手を前へ伸ばす距離（ちょん押しで体の近く、全開で最大リーチ）。小さな不感帯があります。「両腕/左腕/右腕」ボタン（スティックの左隣）で、動かす腕を切り替えられます。
  - 調整スライダ: ポーズ画面の「巨人の操作設定」で、旋回の速さ・移動の速さ・腕スティック感度・カメラ追従の強さを調整できます（自動保存、「初期値に戻す」あり）。
  - 一人称では、頭まわり全体を隠して顔が映り込まないようにしました。
  - ミニマップは、設定の「ミニマップ」チェック・Mキー・画面右上の「地図」ボタンで表示／非表示できます。
- **手を伸ばす（腕の操作）**: スティックをやめ、指した場所へ手が伸びる方式にしました。
  - スマホ: 「🖐 手を伸ばす」をONにし、画面の右側（左38%は移動スティック用）をタッチ／ドラッグします。指の位置の地面（または空中の兵士）へ、近い方の手が伸びます。兵士の近く（画面上60px以内）をタッチすると、その兵士に吸着します（🎯）。指を離しても約0.6秒は手がそこに残ります。ONの間は右側のドラッグでは視点が回りません（カメラは自動追従。OFFで手動）。
  - 距離感: 巨人の足元に「届く範囲」の水色の輪（半径20×スケール）が出ます。狙っている点には、緑の円と「12m 届く」のような距離が出て、届かない場合は橙色で「遠い」と出ます（届く限界へ手が伸びます）。
  - 可動域: 手が届かないときは、自動で しゃがむ・前傾・体をひねる（左右±約50°）ことで届く範囲を広げます。腕の関節の可動域は従来どおり制限されています。
  - 手が兵士に触れれば、これまでどおり自動で掴みます。
  - PC: E を押している間、画面中央の点（照準）へ手を伸ばします（Q は両手）。
- **ミニマップ（巨人のみ・左上）**: 画面の上がカメラの向きです。家・兵士（高い所にいる兵士は白縁）・蹴りの範囲（赤い輪）・巨人の向きが表示されます。範囲外の兵士は縁に小さく出ます。
- **カメラを寄せる**: 「寄る」ボタン（PCは B）で巨人のカメラが近づき、もう一度で戻ります。標準の距離も少し近く（72→60）しました（保存済みの設定はそのまま）。
- **マップ**: 広場（噴水・時計塔・池・オベリスク・ベンチ・街灯）を撤去し、家を約半分に間引きました。オンライン中は霧も半分の濃さです（ソロにも同じマップが使われます）。
- **やられた原因の表示**: 脱落すると画面中央に原因（蹴り飛ばされた／食べられた）、そのときの自分の位置（巨人からの距離・高さと蹴りの範囲）、対策が約6秒表示されます。全員の画面の左上には「○○ 🦵 蹴り」などのキルログが出ます。
- 雷槍で四肢を切断した結果は巨人側にも同期されます（雷槍は遠くから届くため、サーバーは距離 200×スケールまで許容）。
- 巨人の顔が兵士に見えなくなることがある問題を修正しました（一人称で隠した頭が、役割交代後などに隠れたままになっていました）。
- うなじ斬りが決まらないことがある問題を修正しました。サーバーが巨人の直近約0.5秒の位置のどれかで判定する（通信遅延の補償）ようにし、申告後0.25秒の確定時には再判定しないようにしました。
- うなじ守りの表示: 全員の画面に大きな「🛡 うなじ守り発動！」と水色の大きな球（うなじのまわり）が出ます。守りで弾かれた兵士には「🛡 うなじ守りに弾かれた！」が出ます。
- 巨人の操作: 「ダイレクト操作」（標準で有効）では、スティックの向きへ素早く旋回して進みます（旋回 約2.2倍・加速も速い）。標準値を、旋回 4.0・移動 1.1・カメラ追従 30% に変更しました。ポーズ画面の「巨人の操作設定」で変更できます。
- 巨人の一人称では、移動している向きにカメラも自動で合わせます（視点を手で動かした直後の約0.7秒を除く）。
- **巨人の体に弾かれる**: 巨人の体（頭・胴・腕・脚）にすり抜けるように突っ込むと、弾き返されます。四肢を斬るためにダッシュで突っ込むとき、斬れる状態の四肢は通れます。うなじのまわり（7×スケール以内）は、斬りに行けるよう弾かれません。
- 兵士の攻撃は、うなじと四肢のみです。胴体・頭などを斬る、体に当たって削る、といった巨人の体力を減らす攻撃はオンラインでは無効です。
- 腕スティックの可動域: 外側へは大きく、体の内側へは0.6倍まで、下方向は0.75倍まで（反対側や背中側には回りません）。
- 四肢を斬ると、巨人は遅くなる・這う・掴めなくなります（既存の部位ダメージ）。切断は全員に同期されます。
- 試合後は、ホストが「もう一度（役割交代あり/なし）」を選べます。

## 協力モード（巨人役なし）

ロビーで誰も巨人を選ばずに「開始」を押すと、協力モードで始まります（兵士1〜4人）。

- **巨人の動き・攻撃・当たり判定は、ソロプレイと同じ処理**（ソロの「群れ」モード）を、各プレイヤーの画面でそのまま動かします。開始すると壁の4つの門が開き、巨人が次々と侵入します。
- 巨人は各自の画面で別々に動きます（仲間が戦っている巨人は自分の画面には出ません）。仲間は兵士として、全員の画面に表示されます（名前・色・光の柱つき）。
- ソロと同じく、体を斬る・体力を削る・四肢を切る・うなじで倒す、掴まれたら連打で抵抗、などがそのまま使えます。
- **勝利**: 全員の撃破数の合計が目標に届く（兵士1人あたり12体。`server.js` の `COOP_PER`）。**敗北**: 兵士が全員倒れる。
- **仲間の救助**: 食べられた仲間はその場に「倒れた」状態になり、緑の光の柱と救助範囲の輪が出ます。生きている味方が範囲（半径9）内に約3秒いると復活します（60秒以内）。倒れた本人は観戦しながら待ちます。
- サーバーが管理するのは、撃破数の集計・倒れた状態・救助・勝敗だけです。

## 通信と判定の仕組み

- 同期はクライアント権威です。兵士は位置・姿勢・ワイヤー・ガス、巨人は位置・向き・頭・速度・走行・欠損を送り、
  サーバーが 20Hz でまとめて配信します。クライアントは約100ms遅らせて補間表示します。
- 勝敗に関わる判定はサーバーが検証します: うなじ斬り（距離＋背後条件＋守り中でないこと）、掴み（巨人が申告した手の位置と兵士の距離）、
  蹴り（範囲＋高さ、対象はサーバーが決定）、食べる（掴みから2.5秒後にサーバーが確定）、四肢切断（巨人の近く・1部位1回）。
- 切断後30秒以内なら同じ席に復帰できます。接続が切れると画面上部に赤いバナーが出ます。巨人が退出すると試合は終了します。
- 建物の崩壊は巨人側が発生させ、サーバー経由で全員に同じイベントを配信します。

## 調整できる数値

- サーバー側: `server.js` 先頭の定数 `C`（配信Hz、掴み時間、蹴りの半径・高さ、守り、うなじの判定半径、許容距離 など）。
- クライアント側: `public/net.js` の `ONL`（`DELAY` 補間遅延、`TURN_MUL`/`SPD_MUL` 巨人の旋回・速度、`GRAB_REACH` など）。
  `C` と `ONL` で同じ意味の値（蹴りの半径・時間など）は両方を合わせてください。
