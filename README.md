# 巨人 対 兵士（オンライン対戦）

ブラウザゲーム「巨人討伐」をベースにした、巨人1人（手動操作）対 兵士最大4人のオンライン対戦です。
Render の Web Service（Node.js）が **ゲームの配信（HTTP）** と **WebSocket 通信** の両方を担当します。
タイトル画面で「ソロ」（従来のウェーブ制）と「オンライン対戦」を選べます。

## 構成

| ファイル | 役割 |
|---|---|
| `server.js` | 静的配信 + `/healthz` + WebSocket（部屋・ロビー・同期・勝敗判定） |
| `public/index.html` | ゲーム本体（three.js r128 は cdnjs の固定バージョン） |
| `public/net.js` | 通信・ロビー・巨人操作・同期表示・観戦・結果画面 |
| `public/bgm.mp3` | BGM（元の HTML から切り出し） |
| `scripts/bot.js` | テスト用ボット / サーバーの自動検証 |
| `render.yaml` | Render 用設定（free プラン） |

## ローカルで起動

Node.js 18 以上が必要です。

```bash
npm install
npm start            # http://localhost:3000
```

ブラウザのタブを2〜3個開き、1つ目で「オンライン対戦 → 部屋を作る」、他のタブで表示された4文字のコードで「参加」します。
役割（巨人は1人まで）を選び、ホストが「開始」を押します（最少2人）。

### ボットで動作確認

```bash
npm test                                                  # 部屋・判定ロジックの自動検証（別ターミナルで npm start 済みなら不要。単体で起動しているサーバーに接続）
node scripts/bot.js --room ABCD --count 3                 # 兵士ボット3体を部屋 ABCD に参加させる
node scripts/bot.js --room ABCD --role giant              # 巨人ボットを参加させる（人間2人が揃わなくても開始できる）
node scripts/bot.js --selftest --url ws://localhost:3000  # 接続先を指定
```

`npm test` は `npm start` を起動した状態で実行します。

## Render にデプロイ

1. [Render](https://render.com/) にログインし、GitHub アカウントを連携します。
2. **New + → Blueprint** を選び、push したリポジトリを指定します（`render.yaml` が読まれます）。
   手動で作る場合は **New + → Web Service** で、Runtime: Node / Build Command: `npm install` / Start Command: `npm start` / Plan: Free、Health Check Path: `/healthz`。
3. デプロイ完了後、`https://<サービス名>.onrender.com` を開けば遊べます。URL を友達に送ってください。
   クライアントは同一オリジンの `wss://` に自動接続します（URL の書き換えは不要です）。

### 無料プランの注意

- 一定時間アクセスがないとサービスが停止し、次のアクセスで起動に最大1分ほどかかります。
  接続待ちの間は「サーバーに接続中…」と表示され、自動で再試行します。
- サーバーは 25 秒ごとに WebSocket の ping を送って接続を維持します。
- 部屋はメモリ上にあるため、再起動すると消えます。

## 遊び方

| | PC | スマホ |
|---|---|---|
| 兵士 | 既存どおり（WASD / マウス / Q・E ワイヤー / Shift ガス …） | 既存どおり |
| 巨人 移動 | WASD（向きはカメラ基準）、マウスで視点 | 左スティック |
| 巨人 走る | Shift | 「走る」ボタン |
| 掴む（前方のみ） | 左クリック | 「掴む」 |
| 踏みつぶし | 右クリック / Space | 「踏みつぶし」 |
| うなじ守り | C | 「うなじ守り」 |

- **兵士の勝ち**: 巨人のうなじを背後から斬る。 **巨人の勝ち**: 兵士全員を食べる／つぶす。
- 掴まれた兵士は約2.5秒後に食べられ脱落します。踏みつぶしは半径 8×スケール・高さ4以下の兵士が対象（クールダウン4秒）。
- うなじ守りは持続1.5秒・クールダウン10秒。発動中はうなじを斬れず、巨人も動けません。
- 脱落した兵士は観戦になり、クリック / Tab で巨人・生存兵士の視点を切り替えられます。
- ガス補給所（背の高い建物の屋上に2か所、緑の円盤）で兵士のガスが回復します。
- 四肢を斬ると、巨人は遅くなる・這う・掴めなくなります（既存の部位ダメージ）。切断は全員に同期されます。
- 試合後は、ホストが「もう一度（役割交代あり/なし）」を選べます。

## 通信と判定の仕組み

- 同期はクライアント権威です。兵士は位置・姿勢・ワイヤー・ガス、巨人は位置・向き・頭・速度・走行・欠損を送り、
  サーバーが 20Hz でまとめて配信します。クライアントは約100ms遅らせて補間表示します。
- 勝敗に関わる判定はサーバーが検証します: うなじ斬り（距離＋背後条件＋守り中でないこと）、掴み（距離＋前方＋両腕欠損でない）、
  踏みつぶし（範囲＋高さ＋クールダウン、対象はサーバーが決定）、食べる（掴みから2.5秒後にサーバーが確定）、四肢切断（巨人の近く・1部位1回）。
- 切断後30秒以内なら同じ席に復帰できます。接続が切れると画面上部に赤いバナーが出ます。巨人が退出すると試合は終了します。
- 建物の崩壊は巨人側が発生させ、サーバー経由で全員に同じイベントを配信します。

## 調整できる数値

- サーバー側: `server.js` 先頭の定数 `C`（配信Hz、掴み時間、踏みつぶし半径・クールダウン、守り、うなじの判定半径、許容距離 など）。
- クライアント側: `public/net.js` の `ONL`（`DELAY` 補間遅延、`TURN_MUL`/`SPD_MUL` 巨人の旋回・速度、`GRAB_REACH` など）。
  `C` と `ONL` で同じ意味の値（掴み距離・クールダウン）は両方を合わせてください。
